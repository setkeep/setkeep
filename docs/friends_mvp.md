# フレンドMVP

一般版ホーム下部のカードから、フレンドのトレーニング詳細と既存3D筋肉ヒートマップを開く。いいねは1ユーザー1件、コメントは1〜140文字。自分のいいねとコメントは取り消せる。表示名・写真はマイページで管理し、フレンドでも同じ表示名を使う。相手から受け取ったUUID招待コードまたは招待リンクで相手を確認して申請する。相手だけが承認でき、双方が申請取消・拒否・解除できる。

公開は初期値「非公開」。申請・承認時の確認で「記録を共有して続ける」を選ぶか、公開範囲の変更に明示的に同意した場合、既存履歴も含め日時・種目・セット・所要時間を共有する。場所・メモ・体重・TRAINER識別情報は送信しない。共有にPremium権限は不要。アカウントとSupabase接続は必要。

共有は `friend_workouts` の専用スナップショット。通常 `workouts` / Premiumバックアップ / TRAINER認可・同期は変更しない。記録保存・編集・削除・Undo時にローカル保存後、共有を直列で更新する。更新は1トランザクションでupsert＋削除、同じ日時のID・リアクションを保持する。削除時はリアクションもcascade。履歴の初期ロード完了前に空の共有スナップショットを送らない。ホームの読み込み・更新、設定保存で再試行する。オフラインの記録変更はローカルへ残り、オンラインで更新するまで以前の共有が残る可能性がある。

非公開に戻した場合、RLSが既存共有・リアクションへのフレンドアクセスを直ちに拒否する。フレンド解除も同様。スナップショット自体は保持し、再公開で履歴を再同期する。すでに画面上に表示済みの情報は、画面更新時に再認可される。ホームは各フレンドの最新1件、詳細/ヒートマップはサーバーの直近最大1000件を対象とする。画面表示・アプリ復帰・操作後と下へのスワイプで更新する。更新ボタンや定期ポーリングは使わない。

## 追加DB反映（ローカル草案・本番未適用）

既存の `20261004100000_friends_mvp.sql` は本番反映済み。今回追加した `20261004140000_friends_profile_invites.sql` は別途確認・承認して適用する。写真・招待の相手名プレビューを有効化するには追加migrationが必要。列がない既存DBでは写真変更を非表示、既存RPCで接続を取得し、承認済みの各フレンドの最新1件を既存テーブルから取得する。旧アプリで使う既存RPCは残す。

追加内容は `friend_profiles.avatar_path` と所有者パス制約、非公開Storage bucket `friend-avatars`（PNGのみ・512KiB上限）、所有者の書込と公開同意済みの承認済みフレンドの読取RLS（permissive4件＋restrictive guard5件）、招待の最小プレビュー・最新1件・写真付き接続一覧の3RPCとインデックス。既存のvisibilityを変更する処理はない。通常workouts・TRAINER・バックアップには変更を加えない。

写真は既存image_pickerで選択し、中央を256×256のPNGへ再符号化する。写真のメタデータは送らない。保存後に旧ファイルを削除し、削除失敗でも旧パスはフレンドの読取対象から外れる。表示用署名URLは60秒で失効する。公開解除後にも表示済み画像や発行済みURLを完全に回収できるわけではない。

検証環境で2本のmigrationと `supabase/tests/friends_mvp.sql`・`supabase/tests/friends_profile_invites.sql` を実行する。テストfixtureは合成データでrollbackする。ローカルPostgreSQLのAuth/Storage互換スキーマでRLSを検証済み。実際のStorage APIでのアップロードとOSの写真選択は実機確認が必要。

## 招待リンク

`setkeep://friend-invite/<UUID>` をAndroid/iOSで受け付け、ログイン前の招待を端末に保存し、ログインと既存の初回ゲートを終えてからフレンド画面で確認する。自動申請はしない。自己・無効・既存申請／接続のケースを拒否または案内する。OS共有からLINE等をユーザーが選び、招待コードのコピーも残す。

所有が確認できる公開HTTPS招待ドメイン、Universal/App Links、未インストール端末へのストア案内は今回のリポジトリには未設定。実在を確認できないURLを用意して共有しない。登録済みアプリへのカスタムスキーム＋コードの共有まで実装済みで、LINEによるHTTPSリンク遷移は未完了。

`FRIEND_INVITE_BASE_URL=https://<確認済みホスト>/<招待パス>` をビルドへ渡す場合は、先にそのHTTPSページがUUIDを受けてアプリ起動または正しいインストール先を案内することを確認する。HTTPSリンクの受信は同じoriginと設定パスに限定する。HTTPS公開ページ・関連付けファイル・ストアURL・ネイティブの関連付け設定には別途作業が必要。新規ホスティングや公開・本番設定変更はしていない。

追加草案のロールバックは新アプリを戻した後、transaction内で `supabase/rollback/20261004140000_friends_profile_invites_access_stop.sql` を実行する案。新3RPCの実行を止め、写真bucketだけをrestrictive policyで拒否する。写真・プロフィール・元MVP・通常workouts・Auth・TRAINERと他bucketを残す。本番では未実行。別途完全削除が必要ならStorage APIで物理ファイルを削除した後にschema整理を検討する。元MVPの5テーブルと6RPCを今回の追加草案の復旧で削除しない。

## コメント通知

ホームcardにコメント件数を表示。右上ベルにフレンド・トレーナーの合計未読を表示し、通知画面は「フレンドから」「トレーナーから」の分類とそれぞれの件数を示す。フレンド通知は自分の共有記録への他の承認済みフレンドのコメント。tapで該当sessionとコメントを開き、表示できたコメントだけ既読にする。既存のトレーナー通知・既読RPCを保持する。

通知は既存MVPのコメント・記録・接続から取得し、新migrationは不要。自分の投稿・他人の記録・未承認者を除外し、解除・非公開・コメント／記録削除後は再取得とtap時に再確認する。既読IDはアカウント別に端末へ保存するため、別端末／再インストールとの既読同期はない。OS pushは未実装。既存ベルの表示・復帰・30秒更新と操作後／pull-to-refreshで再取得する。
