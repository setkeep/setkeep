# SETKEEP / SETKEEP TRAINER 現行仕様

更新日: **2026-09-27**

確認基準: `main` の `52ca7ba`、アプリ実装、種目・Vitalマッピング、Supabase migration。`docs/qa/` と過去の制作記録は当時の証跡であり、現在の公開数や実装状態を示すものではない。コード実装、テスト、実機確認、接続先DBへの適用は区別する。

## ブランド・スプラッシュ・SNS画像

- SETKEEPの正式アクセントカラーは `#C7F36B`、SETKEEP TRAINERは `#38C6FF`。`#00D084`、`#04D497` などの旧色を正式色として扱わない。
- SETKEEPの基本ロゴは「SKマーク + SETKEEP」。SNS用画像にはタグラインを付けない。一般版の現行ネイティブスプラッシュには `TRAIN TODAY. KEEP GROWING.` が含まれ、iOS Simulatorでも表示を確認した。TRAINERのスプラッシュにはタグラインがない。
- 両アプリのAndroid / iOSネイティブスプラッシュは、それぞれの正式ロゴを表示する実装。TRAINERは水色のブランド表現を使う。iOS Simulatorでの表示確認と、実機での起動直後の見え方は区別する。
- SETKEEPのSNS用画像は、左上に背景透過の縦型ロゴ（上: SKマーク、下: SETKEEP）を置く。白いカードやタグラインは付けない。ロゴ以外の日付、種目名、重量・回数・セット数、文字サイズ、余白、行間、背景、保存処理は既存レイアウトを維持する。

## SETKEEP一般版

### アカウント切替時のフレンド共有（2026-10-06・ローカル修正）

- 端末内の履歴は従来どおり引き継ぐ。UID別の履歴移行・所有権移譲画面は追加しない。
- 新規トレーニング開始時のアカウントを共有用の出所として記録し、下書き再開・保存再試行でも変更しない。所有者が分からない旧記録をログイン先に割り当てない。
- 旧記録は端末と既存のサーバー共有に残す。出所が不明な旧記録の編集・削除は共有へ送らない。この制限はユーザー了承済み。
- 起動・復帰・フレンド表示・TRAINER取り込みで共有を新たに開始しない。明示的な保存に由来する、同一アカウントの所有者確定済み送信・削除の再試行だけを行う。非公開・未同意の共有内容は送らない。
- 共有は追加・更新と明示的削除だけを扱い、空の端末や端末にない履歴で既存共有を消さない。サーバーの非公開設定は自動で有効に戻さない。
- 新規の申請・承認時には既存の共有確認を使う。承認済みフレンドだけがいる非公開ユーザーには共有再開の専用導線がなく、必要性は未決定。
- 追加migration `20261006170000_friend_owned_sharing.sql` はローカルDBで検証済み、本番未適用。サーバー非対応時は安全な共有送信を停止し、記録と送信待ちを保持する。旧クライアントの自動公開はこの追加SQLだけでは止まらない。
- 静的解析・自動テストと実機確認は区別する。今回の修正の実機・本番E2E確認は未実施。詳細は[共有安全対策QA](qa/friend_owned_sharing_2026-10-06.md)を参照。

### 部位分析と3D筋肉マネキン

- マネキンの向きは**正面・背面の2状態**。側面表示と方向切替ボタンはない。
- マネキン表示枠のどこをタップしても正面と背面が交互に切り替わる。筋肉ヒートマップと履歴集計は維持する。
- このマネキンは部位分析用であり、Vital動画による種目フォームガイドや旧自作3Dフォームとは別機能である。

### Android休憩タイマー

- 実行中は通知・ロック画面に残り時間を表示し、通知から**一時停止／再開、+30秒、セット完了**を操作する。
- 一時停止しても通知と残り時間を保持する。一時停止中の経過時間は引かず、その間の+30秒とセット完了も受け付ける。再開時は保持した残り時間から進める。
- セット完了はトレーニングのセット進行・保存と連動する。次の休憩を始める条件がない最終セットでは新しいタイマーを起動しない。
- 上記は現行Android実装であり、**Galaxy実機確認完了はユーザーの確認報告に基づく**。過去の[休憩通知UI QA](qa/android_rest_notification_ui_2026-09-24.md)は修正前の履歴で、現在の未対応TODOではない。iOSの休憩タイマー挙動はこのAndroid仕様から推定しない。

### トレーナーからのメニュー・コメント

- SETKEEPホーム右上のベルから既存の「トレーナーからのメニュー・コメント」画面を開く。新着メニュー・コメントの未読数をベルに表示し、99件を超えた表示は `99+` とする。未読0件はバッジを表示しない。
- 未読状態はSupabaseでログインユーザーごとに管理する。件数は `tenant_inbox_unread_count`、既読更新は `tenant_mark_inbox_seen` を使用し、メニュー・コメントそれぞれのversionを渡す。内容を正常に取得・確認できた後に既読へ更新し、読み込み失敗時は既読にしない。
- 認証状態の変更、アプリ復帰、定期更新で件数を更新する。旧仕様書の「ベルと未読バッジは未完了」は現行仕様ではない。
- 現行UIには**別の「トレーナーからのメニュー・コメント」ボタンは見当たらず、ベルが導線**である。「既存ボタンからも遷移」は現行コードでは確認できないため、仕様としては書かない。

## SETKEEP TRAINER代理記録

- TRAINERが顧客のセッションを記録すると、共通Supabaseの `workouts` に本人の `user_id`、`record_source='trainer'` で保存する。一般版は起動、ログイン、フォアグラウンド復帰、連携承認時に自動同期する。手動受信ボタンはない。
- 一般版の取り込みは `workouts.id` で重複を防ぎ、`canceled_at` による取消・復元を反映する。本人記録や出所を確定できない旧手動受信済み記録を代理記録の取消によって削除しない。通信失敗時はローカル履歴を維持する。
- 新規セッションは種目ごとに1セットから開始し、一般版と共通の数値入力部品を使ってセットを追加・削除できる。既存セッションの保存済みセット数は勝手に変更しない。
- トレーナーコメントはセッション本体の `workouts.note` に保存し、一般版のトレーニング詳細で「トレーナーからのコメント」として表示する。6引数RPCは本番接続先へ適用済み。Galaxyの2アカウントE2Eで保存・自動同期・詳細表示を確認した。

## Vitalフォームガイドと種目画像

Vital Animations動画を製品の種目フォームガイドとして使用する。明確に照合できたSETKEEP種目だけに動画を設定し、詳細画面では自動再生・無音・ループ・操作バー非表示とする。旧自作3Dフォームへはフォールバックしない。Vital動画のない種目は未対応のまま扱い、近い動画を自動代用しない。種目ID、履歴、お気に入り、店舗設備との対応はVital IDで置き換えない。

2026-09-27の `tool/exercise_forms/catalog.json` と `tool/vital_media/mapping.json` の集計:

| 項目 | 現在値 | 数え方 |
| --- | ---: | --- |
| SETKEEPカタログ全種目 | 221 | 旧ID互換を含むカタログ行数 |
| Vital動画への直接対応 | 109種目 | `mappings` の件数 |
| 採用Vital動画 | 108本 | 対応の `providerAssetId` の重複を除いた件数 |
| 要確認 | 91種目 | `reviewRequired` の件数。旧ID `cable_pullover` を含む |
| 該当動画なし・未採用 | 20種目 | 直接対応・要確認・下記の継承1件を除く |
| 旧ID互換 | 2件 | `triceps_pushdown → rope_pushdown`、`cable_pullover → straight_arm_pulldown` |

旧IDのうち `triceps_pushdown` は正規IDの動画を継承するため、直接対応109件とは別に数える。`cable_pullover` は要確認に含め、動画対応済みとは数えない。Vital側の全素材数や、過去の97種・96本などを現行の採用数として使わない。

マッピングは名称だけで決めない。器具、マシン形式、グリップ、軌道、姿勢、対象筋、MP4の実フレームを照合し、不確実なら未対応に残す。Vital ID `0157` は `seated_row` にのみ採用し、`dy_row`、`low_row`、`linear_row`、`high_row` には使わない。Vital動画が存在するだけで新しいSETKEEP種目を自動追加しない。

種目一覧は動画を再生しない。Vital対応種目はVital由来の静止サムネイルを表示し、非対応種目は薄いグレーのSETKEEPロゴをプレースホルダーにする。旧自作3Dから生成した `assets/exercise_thumbnails/` を製品UIの画像やフォールバックに使わない。一般版とTRAINER版はこのルールを共用する。

旧自作3Dフォーム関連のモデル・制作データは開発、QA、比較用として残り得るが、現行製品のフォームガイドや一覧画像の公開状態を示さない。旧第1バッチ、再制作数、検証件数は[旧3D QA履歴](qa/forms_rebuild_2026-09-22.md)などを参照する。部位分析の3D筋肉マネキンは維持する。

購入したVitalのMP4・JSONと生成サムネイルはGitHubへcommitしない。`local_assets/vital_animations/`、`assets/vital_videos/`、`assets/vital_thumbnails/` はGit管理外とし、採用した動画とサムネイルだけをローカルのアプリビルドに含める。402本を無条件に同梱しない。Gitには対応表、生成・監査ツール、自作コード、文書を置く。

## 店舗の営業状態・店舗報告（2026-09-29追記）

- `gym_stores.operational_status`はactive/preopening/temporarily_closed/closed/unknown。
  既存activeは維持し、休業・開業前は検索可/新規利用不可、閉店は通常検索外/既登録から参照可とする。
- 店舗詳細の「店舗情報を報告」と検索の新店舗報告を、既存Evidence/Candidate/判定/適用基盤へ統合。

## 登録済み店舗設備の公開方針（2026-09-30確認）

- 公式HP由来という理由だけで登録済み設備を一律非公開にする方針は採用しない。
  既存の店舗別マシン一覧、登録済みメーカー・型番・台数、共通マッピングと複合設備ルールによる
  「この店舗でできる種目」を表示する。利用者報告・確認票がまだない設備も表示対象。
- 最新mainと本番DBを確認した結果、一律公開停止の実装はなかった。
  現行RPCは`presence_status=present`の設備を返し、対応種目は利用可能台数と必要設備の充足を検証する。
  撤去済み設備を復活させず、一時利用不可の設備は状態表示を維持し対応種目の根拠に使わない。
- 元のID・出典・確認日時を保持する。今回の再確認を現地確認・利用者確認へ付け替えない。
  メーカー・型番・台数の不明値を補完しない。未取得/一部取得を「設備なし」とは扱わない。
- 既存の利用者報告、任意設備確認（スキップ可能）、審査・競合判定・変更履歴・rollbackを維持。
  既知設備について任意確認を繰り返し要求しない。
- **既存データの公開と、新規/定期取得は別管理。公式サイト取得のCron・全体設定・取得先は無効のまま。**
  全国マスター再投入・新規調査・収集再開は行っていない。
- 件数・表示検証・未対応設備の範囲は[公開方針確認QA](qa/equipment_publication_2026-09-30/README.md)を参照。

## トレーニング後の任意設備確認（2026-09-29追記）

- 設備情報の追加は、保存済み完了トレーニングの有効セットからレビュー済み逆引き候補を探し、
  新規候補だけ本人に確認する方式を主導線とする。既存店舗設備・出典はそのまま維持する。
- 一意な候補も明示確認を要求。曖昧な候補は選択式。「その他 / 判定しない」、
  **スキップ・Back・画面を閉じる**を許容し、その場合は票を作らない。
  トレーニングの保存・下書き削除を先に確定するため、確認操作や通信の成否に保存を依存させない。
- 既知の設備は再質問しない。同じユーザーの票はstore×equipmentで1件に集約。
  初期の確定条件は既存addedルールの30日内3人/支持3/反対0を使用する。
  既存Candidate/競合判定/監査/rollbackを再利用し、履歴だけでは確定しない。
- 既存の設備修正・撤去報告は残す。履歴の非利用/削除だけで確定設備を撤去しない。
  履歴編集・削除・Undoは本人確認票の有効性へ反映する。
- 公式サイト取得基盤は引き続き無効。写真投稿は追加しない。
- 実装範囲・プライバシー・検証・制限は[任意設備確認QA](qa/training_equipment_2026-09-29/README.md)を参照。

## 一般版の広告基盤（2026-10-01更新）

- 一般版HOME下部、既存ナビゲーションの上にAdaptive Bannerを1枠配置する。
  TRAINERは広告なし。アプリ起動広告・リワード広告は導入しない。
- 新規トレーニングの完了処理開始時にInterstitialを事前ロードし、記録保存・下書き削除・任意設備確認を必ず先に完了する。
  トレーニング完了時は毎回表示候補とし、端末のローカルカレンダー日ごとに実表示を最大1回とする。
  SNS画像を保存した場合は保存成功後、保存しない場合はHOMEへ戻る直前に最大1回だけ試行する。
  表示直前にロード中なら最大1秒だけ待ち、未ロード・失敗・バックグラウンド時はスキップする。
  SDKが全画面表示を通知した場合だけ当日表示済みとして端末内へ保存し、失敗時は同日に再挑戦できる。
  広告処理は保存・画像生成・遷移を妨げない。
  編集・履歴からの画像作成・トレーニング中・セット間・休憩中は対象外。
- `google_mobile_ads` 9.1.0とGoogle公式のAndroid/iOSサンプルApp ID・Banner/Interstitial IDを使用する。
  **現在はテスト広告のみ**。`SETKEEP_ADS_MODE`の既定値は`test`。
  `off`・`production`・未知の値では広告要求しない。本番IDの入力口はまだ有効化していない。
- `AdsConfig`、`AdsEntitlement`、Banner/Interstitialの共通SDK境界に集約。
  将来、検証済み権利を`setkeepAdsEntitlement.adFree`へ接続すると全広告の生成/要求を停止する。
  Premium判定には接続しない。**広告削除150円/月は予定のみで、課金・購入・復元は未実装**。
- ロード中/失敗/オフライン時は広告領域を非表示。起動・HOME・トレーニングを待たせず、
  自動リトライループなし。広告削除状態への変更、別タブ/画面、バックグラウンドで広告を破棄する。
- SDKは一般版の広告表示条件成立後に遅延初期化する。ログイン/既存規約同意フローは変更しない。
  TRAINERには広告scopeを設置せず、共有依存に含まれるAndroid広告初期化providerを削除する。
- 現段階は開発検証用。ATT/UMP同意画面・プライバシー文面の追加は行わない。
  本番広告導入前にはUMP/EEA等の同意、ATT要否、年齢/子ども向け設定、
  広告識別子、ストアのデータ申告・プライバシー表示を別途確定する。
  非パーソナライズ要求やテストIDは、公開時の同意要件の代替とは扱わない。
- 設定・変更ファイル・検証結果・公開前TODOは[広告基盤QA](qa/admob_2026-09-30/README.md)を参照。
