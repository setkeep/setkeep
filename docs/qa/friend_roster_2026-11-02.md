# 承認済みフレンド全員表示と共有記録の更新順

## 変更

基準は `bbdc531ec195d9a498cb3e995ba7209abdee5ec8`。広告・ジム作業から独立した `fix/friend-roster-updates-20261102` で実装する。

承認済みの接続一覧をカードの母集団にし、通常権限で取得できる共有記録を結合する。閲覧可能な共有記録がないカードは「共有された記録はまだありません」と表示する。私的記録の有無は判定しない。プロフィール欠落時も接続は表示し、名称は「フレンド」にする。申請中・解除済み・現在の本人が参加しない接続は表示しない。

共有記録の取得失敗は記録ゼロと区別し、カード内の読み込み失敗表示と再試行を出す。接続一覧の取得失敗は古い接続を表示せずエラーにする。再取得中は古い内容・操作を隠し、スクロール維持のため高さだけ保持する。古い非同期応答で新しい結果を上書きしない。画面表示・復帰・タブ再選択・管理画面から戻る操作・pull-to-refresh の既存更新経路を使う。

## 更新日時の意味とDB候補

既存スキーマの `performed_at` は運動日時であり、内容の更新日時ではない。既存APIだけで正確な更新順を復元することはできない。

候補 `20261102090000_friend_workout_updates.sql` は、共有スナップショットに nullable な `updated_at`、機能判定用の本人プロフィール列、RLSに従う invoker RPC を追加する。新規共有、日時・所要時間・セット内容の実際の変更でサーバーのSQL文開始時刻を記録する。同じ一括共有の行は同時刻とし、投入順で架空の更新順を作らない。同じ内容の再同期では更新しない。過去の行は NULL のまま残し、運動日や適用時刻による過去の活動の捏造をしない。クライアントが時刻を指定する経路は追加しない。

並び順は、閲覧可能な現存共有記録の更新日時が新しい順、更新時刻不明の共有記録、取得失敗、共有記録なし。同時刻・不明・記録なしでは相手の既存アカウントIDで安定順にする。旧DBでは共有記録あり／なしを区別して安定順とし、運動日を更新時刻の代用にしない。更新順の有効化には候補migrationの別途承認・適用が必要。

削除時は残る閲覧可能な共有記録だけで再計算する。全削除・非公開化で取得結果がゼロになればカードは記録なしへ移る。接続解除または権限上の接続撤回ではカードを除く。削除された記録や非共有記録の更新情報・tombstoneは取得しない。アプリに新しいブロック機能は追加しておらず、接続から除外される場合の表示を検証する。

更新された古い運動日の記録が詳細の1000件の範囲外でも、ID・所有者を指定したRLS付き再取得で詳細を開く。カードのキャッシュだけで詳細を表示しない。
